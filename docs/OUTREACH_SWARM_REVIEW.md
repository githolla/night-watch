# Nine-67 outreach rewrite and review

## Delivered

- 443 newly authored company drafts; 443 distinct subjects and bodies.
- 8 selected second-buyer drafts in the target list.
- 11 separately researched drafts across Trinity Life Sciences and Quantiphi, which were absent from the supplied CSV.
- 462 total draft versions across445 companies.
- Primary proof mix: {'accounts': 62, 'reporting': 36, '20-applications': 27, 'proposals': 74, 'process': 211, 'delivery': 23, 'finance': 10}.

## What changed

Three agents independently reviewed positioning, target fit and the writing pipeline, then divided primary authoring into IDs1–150,151–300 and301–443. All primary assignments were saved. The usage limit interrupted the planned full second-role pass. The parent agent completed local review, corrected duplicate subjects and question counts, revised selected copy and added role alternatives. This is not a claim that an independent second reviewer read and approved all443 emails.

The rewrite removes job-replacement rhetoric and generic founder introductions from reviewed copy. Technology vendors are approached about a bounded internal operating workflow rather than rebuilding the product they sell. Professional-services examples use account visibility, proposals or reporting where relevant. Other industries receive an explicit proposed first build without invented industry experience, ROI, or current pain. The 20-application engagement is used selectively when scale is relevant.

## Application behavior

Company domains are authoritative; similarly named firms are not conflated. The reviewed library is selected by buyer responsibility, not sibling card order. Nearby roles may use the same substantive buyer brief; the system does not pretend a synonym rotation is individual research. The review page labels the intended buyer. The existing general composer remains a fallback for companies/roles outside this library.

Opening an administrator's desk starts a bounded, cursor-based background refresh of untouched reviewed/broken drafts. Rendering never awaits that work. Manual edits, approvals and logged outreach are preserved. Live previews apply a background change only if their text/status is unchanged. Manual refinement is marked edited and checks the original database values before saving. A contact's Reviewed draft action deliberately selects this version with the signed-in sender's settings and preserves sent history.

## Evidence and limits

Public proof: https://www.nine-67.com/case-study. The account-risk view reached production in one month. Reporting is described as built and ready. The owner supplied the20-application deployment fact and application screenshot. No deployment timeline or numeric savings is inferred for that engagement. Public company context for supplemental work: https://trinitylifesciences.com/ and https://quantiphi.com/.

The original target file supplies company context; every recent signal has not been independently reverified. Many software firms are a conditional fit, requiring a relevant internal buyer. No response-rate improvement is measured yet. Assess the first small cohorts by positive replies and qualified conversations; choose one suitable contact per account before expanding within it.

## Validation

216 tests passed, including every reviewed company's domain lookup, greeting/sign-off, length and sending safeguards; stale-preview and edit-preservation checks. Lint and TypeScript passed. Production build validated separately before deployment. No outbound email was sent.
